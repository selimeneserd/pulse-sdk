# Open contracts and extensions / Açık sözleşmeler ve uzantılar

The MIT files in `contracts/` are the public source of truth. `event-v1.schema.json` generates `event.generated.ts`; packaged copies and deterministic package `version.ts` files are generated by `pnpm contracts:generate`. CI `pnpm contracts:check` rejects drift. JSON Schema is normative for field/conditional constraints; generated TypeScript reflects required/optional fields and unions, not all cross-field rules. `core/conformance` validates the supported schema subset without a dependency; Ajv development tests compare it against canonical fixtures and field mutations. Schema URNs identify contracts, not deployed URLs: `urn:pulse:contract:event:1`, `urn:pulse:contract:batch:1`, `urn:pulse:contract:ack:1`. Source documentation is this repository's `docs/contracts.md`; no unverified hosted schema endpoint is claimed.

TR: MIT JSON Schema kanoniktir; tip ve paket kopyaları üretilir, CI drift'i reddeder. URN kimliktir, çalışan URL değildir. Çapraz alan koşullarında şema belirleyicidir.

## Event meaning / Olay anlamı

`kind=tool_handler.completed`, schema_version1: a registered handler returned/resolved/threw; duration_ms covers its monotonic start→settlement. occurred_at is the wall-clock completion instant, UTC RFC3339. It is not the start time or full MCP latency. Adapter outcome reads only result envelope discriminants; request cancellation uses the public request signal. Input validation/authorization before handler and output validation/transport after handler are separate. Business success is unknown. A cancellation before invoking a handler has no completion event; an invoked handler's signal-aborted settlement is `cancelled`.

SDK package version, adapter package version and schema version are independent. Core defaults adapter `custom`; MCP supplies its own name/version. `adapter_version` is optional/additive. Existing events remain readable. Optional old metadata fields remain optional in v1; a new adapter should populate provenance where known. No tenant/project/plan/write-key/billing ID in event payload. Collector authority comes from verified transport credentials.

TR: Süre handler başlangıcıyla dönüşü/settlement arasındadır. Handler sonrası MCP hatası geriye dönük olay anlamını değiştirmez. İş sonucu bilinmez. Şema/paket/adaptör sürümleri ayrıdır; tenant yetkisi gövdeden alınmaz.

## HTTP wire / HTTP teslimi

POST only to the explicitly selected full endpoint. HTTP loopback or HTTPS elsewhere; no redirects, embedded credentials/query/fragment. UTF-8 JSON Content-Type. Request `{schema_version:1,events:[...]}`;1–100 events, max256KiB. Each event ID is stable on every retry. Transport headers/auth are optional collector-specific configuration, never copied into events/diagnostics. Cloud uses its server-only Bearer key.

202 JSON acknowledgement: required accepted IDs, duplicate IDs, rejected items `{event_id,code,retryable}`, server_time RFC3339. Optional next_retry_after_ms between0 and60000. Reject unknown object keys, unknown/batch-external IDs, repeated/conflicting classifications, invalid booleans/codes/time/delay. Treat an invalid acknowledgement as unconfirmed **for the whole attempt**; do not count any accepted. Omitted IDs and retryable:true remain pending. accepted, duplicates and permanent rejected are removed separately; only unconfirmed/retryable IDs are resent. A duplicate is not new accepted usage. Schema validation alone cannot detect IDs from another submitted batch; implementations must correlate IDs too.

401/403 block until explicit resume or exporter reconfiguration; current/queued/new events are dropped with auth reason.408/425/429/5xx/network/malformed responses get bounded retry. Other4xx permanently reject;413 splits without resetting retry budget, single oversize events drop.429 carries no core plan meaning. `Retry-After` decimal seconds or HTTP-date preserves the server minimum without a 60s clamp, including on malformed 202 acknowledgements. The larger of the header and valid body `next_retry_after_ms` applies; the wire body's existing 0–60000 constraint is unchanged. Jitter is half-to-full exponential base capped at `retryMaxMs`; the actual delay is at least the server minimum, rounded up to whole milliseconds for Node timers.

`retryMaxMs` is the **per-delay limit and backoff ceiling**, not a total elapsed retry budget: default 2000ms, configurable 1–60000ms, with `retryBaseMs <= retryMaxMs`. `maxRetries` separately permits 0–3 retries. A valid server minimum above this limit immediately drops only still-pending IDs as `droppedRetries` (and increments `exporterFailures`), without scheduling a timer or an early request. Thus `Retry-After: 120` with `retryMaxMs: 60000` drops; the default 2000ms already dropped this example before the correction. Valid very large numbers/dates also drop before timer allocation. Zero/past dates use the bounded local backoff. Missing, malformed or over-100-character headers preserve the existing local-backoff fallback; the decimal/date grammar is unchanged. Shutdown aborts pending wait within its deadline. No raw headers, responses or errors enter diagnostics.

TR: `Retry-After` alt sınırı 60 saniyeye kırpılmaz; bozuk 202 gövdesinde de korunur. Header ile geçerli gövde gecikmesinin büyüğü kullanılır, kesirli milisaniye yukarı yuvarlanır. `retryMaxMs` toplam süre değil, tek bekleme sınırı ve backoff tavanıdır (varsayılan 2000ms, izinli 1–60000ms); `maxRetries` ayrıca 0–3'tür. Server minimumu sınırı aşarsa yalnız bekleyen olaylar `droppedRetries` ile düşer, erken istek/zamanlayıcı kurulmaz. Sıfır/geçmiş tarih yerel backoff; bozuk/eksik/100 karakterden uzun header mevcut güvenli fallback kullanır. Gövde sözleşmesi ve shutdown sınırı değişmez; ham içerik diagnostics'e yazılmaz.

Acceptance is the configured sink's documented completed admission boundary, **not a universal durable-storage guarantee**. Memory/noop/OTel handoff are explicitly non-durable; JSONL append is not fsync. Cloud202 is after PostgreSQL commit. A reference collector must state its own storage policy. Lost responses may lead to replay; compliant idempotent collectors scope IDs to authenticated project and compare canonical content, not global IDs. Cloud documents its retention/dedup window separately.

TR:202 yanıtı teslim edilen batch ID'leriyle eşleştirilir; çelişkili/bozuk yanıtın hiçbir kabulü sayılmaz. Kısmi kabulde yalnız belirsiz/retryable olaylar yeniden gider. Duplicate yeni kullanım değildir. Auth açık toparlanır, kota core takvimine girmez. Kalıcılık sınırı her sink'te belgelenir; Cloud commit sonrası kabul eder.

## Exporter / adapter authoring

Implement `PulseExporter.export(events,{signal})` with one bounded attempt and return `{accepted,duplicates,rejected,retryAfterMs?}`. Respect signal, snapshot+validate externally supplied events, never log payload/errors/headers. No private imports, second queue/retry loop, mandatory credentials, implicit destination or remote config. Optional `shutdown({signal})` must be bounded. A hostile exporter can hold its own memory/work forever; core prevents additional concurrent attempts and reports `exporter_timeout` until settlement plus explicit recovery. Application-supplied synchronous CPU work cannot be preempted by JavaScript timers.

A thin adapter calls `core.complete({toolName,durationMs,outcome,adapter:{name,version}})` only at observed handler settlement, preserving `this`, arguments, error identity and async/cancellation semantics. Use native monotonic time. Never infer MCP request/business result from handler result. Prefer public registration hooks and fixture-test actual upstream versions. Map dynamic names to fixed safe tool labels or exclude them. CLI/init may copy thin integration only; versioned packages own critical safety/retry code.

Run:

```sh
pnpm contracts:check
pnpm conformance
pnpm identity:check
pnpm test
```

Third-party exporter smoke: `runExporterConformance(exporter,eventFixture)` from `@reviseflow/pulse-core/conformance`; it submits the same frozen public event twice, each with a 1s bound. Dispatcher, smoke and normalized HTTP acknowledgements use the same internal `snapshotExportResult` contract boundary: unknown fields, negative/non-finite delay, out-of-batch/repeated/conflicting IDs, malformed rejections and conflicting controls fail safely. Accessors are read once; owned arrays/rejection records prevent later exporter mutation from changing delivery decisions. The helper is not a public entry point. Runtime validity and smoke success are separate: omitted IDs, retryable or permanent rejection and exclusive block/split controls remain valid runtime results, but do not demonstrate the smoke's required one accepted/duplicate event per attempt. No new complete-batch requirement is imposed. Invalid exporter results return the existing safe `{passed:false,checks}` shape without payload details.

This bounded smoke cannot certify external durability, throughput, privacy of arbitrary exporter internals or a billing guarantee. The repository conformance command also runs positive/negative events and HTTP fixture schemas. `tests/export-result.test.ts`, `tests/dispatcher.test.ts` and real HTTP tests cover partial/duplicate/retry/cancellation behavior.

TR: Dispatcher, conformance smoke ve normalize HTTP yanıtı aynı dahili snapshot doğrulamasını kullanır. Bilinmeyen alan/geçersiz gecikme/çelişkili ID ve kontroller güvenle reddedilir; getter bir kez okunur, sonradan dizi değişimi kararı değiştirmez. Eksik ID ve meşru kısmi yanıt hâlâ geçerlidir; smoke teslim başarısı ayrıca değerlendirilir. Bu tam uyumluluk/kalıcılık sertifikası değildir ve ham hata/sonuç döndürmez.

TR: Dış exporter tek deneme yapar; kuyruk ve retry core'dadır. Public conformance başlangıç kontrolüdür, dış sistemin kalıcılık/gizlilik sertifikası değildir. Adaptör yalnız gözlenen handler sınırında kayıt üretir. Kritik runtime kodu kopyalanmaz; sürümlü paketlerde kalır.

## Independent reference collector / Bağımsız örnek toplayıcı

`node --import tsx examples/reference-collector.ts` starts an explicitly labelled loopback-only ephemeral collector. It imports only the public JSON Schema plus Ajv/Node, no Pulse runtime or Cloud code. It validates schema/limits, partial rejection, stable-ID duplicate and content conflict. Retains only the last1,000 ID+digest entries, no event payload; dedup expires on eviction/restart. No auth/multi-tenant/durable production claim. `tests/reference-collector.test.ts` runs the public HTTP exporter conformance against it. Third parties can replace storage/auth using the documented contract without copying SDK code.

TR: Örnek yalnız loopback test içindir; şema dışında Pulse runtime/Cloud kullanmaz.1.000 ID/hash tutulur, restart/eviction ile dedup biter. Üretim kalıcılığı veya tenant güvenliği iddiası yoktur.
